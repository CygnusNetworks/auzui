A usable Zabbix UI. Finally.

auzui is a fast, dense, dark-mode-first monitoring app that runs next to your existing Zabbix web UI — not instead of it. Configuration stays in classic Zabbix; auzui rebuilds the workflows you use every day on call.

Zero-config deep observability

auzui derives what it can from what Zabbix already knows — item tags, units, templates, trigger expressions, LLD, inventory — instead of asking you to build dashboards, panels and thresholds by hand.

◧

Problems as a live triage board

Virtualized list, inline acknowledge and comment, severity chips, bulk actions and a side panel instead of popups — every filter is a shareable link.

▤

Auto-generated host dashboards

Sections by component, trigger thresholds as chart zones, an interface matrix, storage and certificate forecasts and 7-day ghost lines — no dashboard configuration at all.

▦

Infrastructure Explorer

Heatmap drill-down from host groups to hosts, components and items, coloured by status or utilization, with “top movers” at every level.

◈

Auto-topology

A dependency graph built from trigger dependencies, LLDP/CDP neighbours, shared subnets and event correlation — every edge tagged with its evidence and confidence.

▥

Metric Browser

Faceted search across every item, a small-multiples wall sorted by deviation from baseline, and overlay comparison across hosts.

⌘

⌘K command palette

Jump to any host, item, trigger or dashboard — or run actions like “Ack problem…” — without digging through menus.

◎

Web scenarios

Live status of every Zabbix HTTP check, per-step response times, pass/fail codes, 14-day availability and a one-click enable toggle.

◐

Built for on-call

Dark mode first, high information density, consistent severity colours and skeleton loading instead of spinners.

⚡

InfluxDB fast path optional

Long ranges and dense dashboards via a Flux aggregateWindow query — downsampled on the server from an effluence export.

Runs next to Zabbix, not instead of it

Nothing to migrate. auzui talks to the JSON-RPC API your Zabbix web UI already serves; the classic UI keeps doing configuration and administration. Architecture ↗

1

Single-page app

React 19 + TypeScript with native uPlot charts. Your browser talks to the Zabbix API with your own Zabbix permissions.

2

Zabbix stays as it is

The existing api_jsonrpc.php is the backend, reached only through the gateway. No schema changes, no plugins, no Zabbix code — a clean-room implementation.

3

Small gateway, filtering proxy

auzui-gateway (FastAPI) serves the app and proxies the Zabbix API with a method allowlist and login throttling, so Zabbix can stay internal. It also unlocks InfluxDB, Graylog, Docker and Kerberos — each feature-gated, each hidden when unset.

Deploy in one container

One image holds the gateway and the built app. Only ZABBIX_API_URL is required; everything else is opt-in. Published to GHCR and Docker Hub for amd64 and arm64.

Docker

docker run -d --name auzui \
  -p 127.0.0.1:8080:8000 \
  -e ZABBIX_API_URL=https://zabbix.example.com/api_jsonrpc.php \
  ghcr.io/cygnusnetworks/auzui:latest

Then open http://localhost:8080/ and sign in with your Zabbix account. Put a reverse proxy in front for TLS.

Optional integrations

# InfluxDB time-series
INFLUX_URL / INFLUX_TOKEN / INFLUX_ORG
# Graylog log panels
GRAYLOG_URL / GRAYLOG_TOKEN
# Docker container management
DOCKER_HOSTS / DOCKER_REGISTRIES
# Kerberos SSO
SPNEGO_ENABLED / KRB5_KTNAME

Or a mounted TOML/YAML file via AUZUI_CONFIG_FILE — configuration reference.
